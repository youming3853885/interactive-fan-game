# 影像辨識畫圈對決遊戲 — 設計文件

**日期**：2026-09-05
**狀態**：設計定案，待寫實作計畫

## 一句話

兩名玩家站在攝影機前，各自用整隻手臂畫圈；畫面隨機出「順轉/逆轉」指令，方向做對才累積能量，能量驅動實體風機正反轉與 WS2812 燈帶能量條，誰先集滿誰勝。

## 硬體清單

| 元件 | 用途 | 接法 |
|---|---|---|
| Arduino UNO | 收網頁指令、驅動馬達與燈帶 | USB 接電腦 |
| L298N 雙 H 橋 | 驅動 2 顆 DC 風機，可正反轉 + PWM 調速 | ENA/ENB 接 UNO PWM 腳；IN1–4 接數位腳 |
| 2× DC 馬達風機 | 實體回饋，跟玩家手勢同步正反轉 | 接 L298N OUT1/2、OUT3/4 |
| 2× WS2812B 可定址燈帶 | 實體能量條（逐顆亮 + 玩家配色） | 各一條 Data 腳，FastLED 驅動 |
| 12V 電源 | 馬達供電 | 進 L298N，**與 UNO 共地** |
| 5V 電源 | WS2812 供電（依燈數算安培） | 直供燈帶，**與 UNO 共地** |

### 接腳規劃（UNO，實作時可再調）

- L298N：`ENA=3(PWM)` `IN1=2` `IN2=4`；`ENB=5(PWM)` `IN3=7` `IN4=8`
- WS2812：`燈帶A Data=6`、`燈帶B Data=9`
- Serial：USB（pin 0/1 保留）

### 硬體實體雷（校正旋鈕，非程式能省）

1. **馬達啟停會拉低電壓干擾 UNO** → 馬達用獨立 12V 電源、與 UNO 共地、L298N 電源端加濾波電容。
2. **WS2812 電流隨燈數線性上升** → 5V 電源安培數要照燈數算（每顆全亮約 60mA），不可吃 USB 5V。
3. **DC 馬達啟動電流大** → PWM 下限要設一個「能轉得動」的最小值，低於此直接停轉（死區），實測校正。

## 系統架構

單頁網頁（Chrome kiosk 全螢幕），全部運算在瀏覽器內，零背景程式、零安裝：

```
攝影機 ──> 姿態辨識(TF.js) ──> 遊戲邏輯(能量/方向/速度)
                                      │
                            ┌─────────┴─────────┐
                            ▼                   ▼
                    畫面特效/能量條      Web Serial ──USB──> Arduino UNO
                                                              ├─ L298N ─> 2×DC風機
                                                              └─ 2×WS2812 燈帶
```

**Arduino 只是聽指令的手腳**，遊戲狀態完全在網頁算。韌體極薄：收 `方向+轉速+能量%` 就驅動馬達與燈帶。

### 通訊：Web Serial API

- Chrome/Edge 內建，網頁直接開 USB 串口，免背景程式。
- 展覽情境：單機 Chrome kiosk 全螢幕，開頁時點一次「選擇串口」授權即可。
- 需 `localhost` 或 `https`（本機檔案用 `localhost` 服務即可）。

## 辨識演算法（核心）

「整隻手臂畫圈」偵測，不需訓練模型：

1. 姿態辨識取得**手腕**與**肩膀**關鍵點。
2. 計算手腕相對肩膀的角度 `θ = atan2(手腕.y − 肩.y, 手腕.x − 肩.x)`。
3. 逐幀**解纏(unwrap)** θ，避免 ±π 跳變。
4. 角速度 `ω = dθ/dt`：
   - `sign(ω)` = 順/逆時針 → 決定風機正反轉、比對畫面指令
   - `|ω|` = 畫圈快慢 → 決定風機轉速 PWM + 能量累積速率
5. `|ω| < 門檻` 視為停手（去雜訊）。

### 兩人分辨：畫面左右切半

- 左半畫面 = 玩家 A，右半 = 玩家 B，各跑一個單人姿態辨識。
- 最穩、不會認錯人；玩家站定位即可（地上貼腳印標記）。
- 每人用慣用手（或任一手）畫圈；取該人較活躍那隻手臂當該頻道輸入。

## 遊戲規則

每頻道（A/B）完全獨立運算：

- 畫面各自顯示一個隨機方向指令（↻ 順 / ↺ 逆），每隔 **3~5 秒隨機換一次**（可調常數）。
- 玩家畫圈方向**符合指令** → `能量 += k·|ω|·dt`，畫面在手上噴粒子特效。
- 方向做錯或停手 → `能量 -= 退減·dt`（緩降，**不倒扣**），夾在 0~100。
- **風機永遠跟著玩家真實手勢方向正反轉**（做錯時風機就往反方向轉，玩家自己看得出來不對）。
- 燈帶 = 能量條逐顆亮（玩家配色）。
- 誰先到 **100** → 播勝利特效、定格、宣布勝方，可重新開始。

### 可調常數（校正旋鈕）

`k`（累積速率）、`退減`、指令切換秒數區間、`|ω|` 門檻、PWM 死區下限、燈帶顆數。

## 畫面配置（UI）

```
┌──────────────────────────────────────────────┐
│  [能量條A]                          [能量條B]  │  ← 左右各一條，垂直，對應實體燈帶
│  ▓▓▓▓░░░      攝影機畫面 + 骨架疊圖     ▓▓░░░░░  │
│  玩家A 45%       ↻(A指令) ↺(B指令)     玩家B 22%│  ← 各自方向指令箭頭
│                                                │
│                    ◉ 唱盤(旋轉)                 │  ← 音樂切換小工具（底部一角）
└──────────────────────────────────────────────┘
```

- **兩側能量條**：左右各一條垂直能量條，顏色對應該玩家/燈帶，即時鏡射實體 WS2812 進度，直覺可看。
- **方向指令**：各玩家頭上/該側顯示大箭頭 ↻/↺，切換時有動畫提示。
- **音樂唱盤（小工具）**：畫面底部一角一個旋轉唱盤圖示，點一下切換曲目；播放中唱盤持續旋轉、暫停則停。
  - 先用**佔位曲目**（1~2 首內建 placeholder，或無聲佔位），旁邊一個「上傳」按鈕 `<input type="file" accept="audio/*">`，之後可自行上傳 MP3 加入清單。
  - 用原生 `<audio>` 播放，唱盤旋轉用 CSS 動畫；不引入音訊函式庫。與遊戲邏輯無耦合，純氣氛。

## 通訊協定

網頁 → Arduino，約 20–30Hz，一行 ASCII：

```
A,F,180,45;B,R,200,60\n
```

= A 頻道正轉/PWM 180/能量 45%；B 頻道反轉/PWM 200/能量 60%。

- 方向：`F`=正轉 `R`=反轉 `S`=停
- PWM：0–255
- 能量：0–100
- **單向即可**，網頁是唯一真相來源。韌體解析這行後直接下馬達與燈帶。

## 模組邊界

| 模組 | 職責 | 依賴 |
|---|---|---|
| `pose`（辨識層） | 攝影機 → 每幀左右手腕/肩座標 | TF.js、webcam |
| `motion`（純函數） | 角度解纏、ω 計算、方向判定 | 無（可單測） |
| `game`（純函數） | 能量積分、指令狀態機、勝負判定 | `motion` 輸出 |
| `protocol`（純函數） | 遊戲狀態 → serial 字串 | 無（可單測） |
| `serial`（傳輸層） | Web Serial 開串口、送字串 | 瀏覽器 API |
| `firmware`（Arduino） | 解析字串 → 驅動 L298N + FastLED | — |
| `ui`（畫面層） | 攝影機疊圖、左右能量條、指令箭頭、特效 | `game` 狀態 |
| `music`（小工具） | 唱盤切換/播放曲目、上傳 MP3 | 原生 `<audio>`（與遊戲無耦合） |

核心（`motion` / `game` / `protocol`）是純函數，攝影機與串口是薄轉接層。

## 測試策略（TDD）

1. **純函數單測**（Node + vitest，免攝影機/硬體）：
   - `motion`：餵已知假 landmark 序列 → 驗證 ω 正負與大小正確、解纏無跳變。
   - `game`：餵方向序列 → 驗證方向對才漲、做錯只緩降、到 100 判勝。
   - `protocol`：餵遊戲狀態 → 驗證輸出字串格式正確。
2. **Sim 模式**：把 serial 指令印在畫面上而非送串口 → 沒接 Arduino 也能玩、能 demo。
3. **韌體自測**：Arduino 開機跑一次馬達正反轉 + 燈帶跑馬燈自檢，確認接線正確。

## 明確不做（YAGNI）

- 不做多人（>2）、不做連線對戰、不做排行榜/帳號。
- 不做雙向 serial 握手（網頁單向下指令就夠）。
- 不訓練自訂模型（用現成姿態辨識）。
- 不做風機底座擺頭（只做扇葉正反轉）。
