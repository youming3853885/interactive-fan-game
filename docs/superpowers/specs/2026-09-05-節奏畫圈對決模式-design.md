# 節奏畫圈對決 (Rhythm Circle Duel) — 遊戲模式重設計

**日期**：2026-09-05
**狀態**：設計定案，待寫實作計畫
**取代**：原本「亂數各自出方向 + 能量先滿者勝」的模式

## 一句話

兩名玩家看**同一份依 BPM 生成的段落表**，跟著音樂在「正轉／反轉／休息」段落畫圈；做對方向且合拍會加分、連續做對疊 combo；限時（2 分鐘或整首）結束後**比分數高者勝**。

## 進場流程（門檻：抓到雙手才開始）

1. **選歌**（可試聽；此時遊戲音樂尚未開始）。
2. **準備階段**：畫面提示兩位玩家站定位、揮手讓鏡頭看到手；左右各出現一個方塊，各自把手放進去**維持 5 秒**。
3. **雙方都就緒**後 → **音樂（MV）開始播放**，段落表時間軸 `t=0` 對齊音樂起點，**遊戲同時開始**。

> 音樂只在遊戲正式開始時才播（不在選歌時播），確保節拍與段落表同步。

## 段落表（依 BPM 自動生成，純函數、可測）

`chartFromBpm(bpm, stars, roundSec)` → `[{ dir, startSec, endSec }]`，`dir ∈ {'F','R','S'}`。

- `beatSec = 60 / bpm`。
- **每段拍數** `segBeats`：難度越高越短 → `segBeats = stars>=4 ? 4 : 8`（低難度一段 8 拍、高難度 4 拍）。
- **段落樣式**：循環樣式陣列，難度越高休息越少：
  - `stars<=3`：`['F','R','S']` 循環（正、反、休 各一段）
  - `stars>=4`：`['F','R','F','R','S']` 循環（休息更稀、切換更密）
- 從 `t=0` 起，依樣式逐段填入，每段長 `segBeats * beatSec`，直到累積時間 `>= roundSec`；最後一段裁切到 `roundSec`。
- **完全決定性**（不用亂數），同 `(bpm, stars, roundSec)` 產生同一份表 → 好測、雙方一致。

## 計分（混合：持續 + 合拍加成 + Combo）

每幀對每位玩家：`scoreStep(state, segDir, omega, dt, cfg)` → 新 `{ score, combo }`（純函數、可測）。

- **休息段（`S`）**：不計分、**combo 保留**（設計好的暫停不算斷）、風機停。
- **活躍段（`F`/`R`）**：
  - `moving = |omega| >= cfg.deadzone`
  - `correct = moving && dirOf(omega) === segDir`
  - `correct` 為真：
    - `onTempo = |omega|` 落在 `[cfg.tempoLo, cfg.tempoHi] * targetOmega` 內 → `tempoMult = cfg.tempoBonus`（例 1.6），否則 `1`（轉太快仍給基礎分）
    - `combo += dt`；`comboMult = min(cfg.comboMax, 1 + Math.floor(combo / cfg.comboStep))`
    - `score += cfg.baseRate * dt * tempoMult * comboMult`
  - `correct` 為假（方向錯或停手）：`combo = 0`，不加分。
- **目標轉速** `targetOmega = cfg.revsPerBeat * 2π / beatSec`（預設 `revsPerBeat = 0.5`，即每 2 拍一圈）。

### 可調常數（校正旋鈕）

`deadzone`、`baseRate`、`tempoBonus`、`tempoLo/tempoHi`、`comboStep`、`comboMax`、`revsPerBeat`、`segBeats`、休息樣式。

## 畫面

- 中央大大顯示**目前段落**（↻ 正轉 / ↺ 反轉 / ⏸ 休息）+ 目前 **combo 倍率**。
- 旁邊小字**倒數下一段**：「下一個：反轉 3..2..1」。
- 上方剩餘時間、雙方分數。
- 沿用：**左藍右紅**、**手掌圖示**、**畫圓導引圓**（導引亮點沿圓移動的速度＝`targetOmega`，玩家跟著它畫就合拍）。
- 分數呈現：畫面分數條 + **實體 LED 燈條同步填**（＝分數進度）。

## 回合結束

- **長度模式**：2 分鐘 → `roundSec = min(120, songLen)`；完整曲 → `roundSec = songLen`。
- 畫面顯示**整首歌時長**（讀 MV metadata）。
- 時間到 → 停止計分、播結算：**分數高者勝**（平手則同分平手）。4 秒後回選歌。

## 實體連動

- 風機永遠跟玩家**真實手勢**方向/轉速（不變；休息段自然停手→風機停）。
- LED 燈條 = 該玩家**分數進度條**（分數 / 目標上限對應燈數；上限可設或用當局最高分正規化，先用固定 `cfg.scoreForFullBar`）。

## 模組變更

| 檔案 | 變更 |
|---|---|
| `src/chart.js`（新） | `chartFromBpm(bpm,stars,roundSec)` + `segmentAt(chart,t)`（查當前段/下一段），純函數 |
| `src/score.js`（新） | `scoreStep(...)` 計分+combo，`targetOmegaFor(bpm,cfg)`，純函數 |
| `src/game.js` | 移除亂數方向/能量狀態機；保留 `fanCommand`（風機跟手勢）、`direction`；`CONFIG` 併入新常數 |
| `src/ui.js` | 目前段落大字 + combo + 倒數下一段 + 剩餘時間 + 雙方分數；導引圓亮點速度改用 `targetOmega` |
| `src/main.js` | 進場流程門檻（就緒才播音樂+起跑）；回合計時器；段落查詢驅動計分；時間到結算 |
| `src/settings.js` / 選歌 | 每首長度模式（2分鐘/完整曲）、顯示整首時長 |
| `src/select-screen.js` | 長度切換 + 時長顯示；波形移到最底獨立帶不重疊、波動加強 |

## 測試策略（TDD）

純函數單測（Node + vitest，免鏡頭）：
- `chart.js`：給 `bpm/stars/roundSec` → 驗證段落總長涵蓋 roundSec、樣式循環正確、`segmentAt` 回傳正確的當前/下一段。
- `score.js`：休息段保留 combo、活躍段做對加分且 combo 隨時間升、做錯歸零、合拍加成生效、目標轉速計算正確。
- 既有 `motion/protocol/tracks/settings/ready` 測試維持綠燈。

## 明確不做（YAGNI / v2）

- 手工譜面編輯器——先全自動生成。
