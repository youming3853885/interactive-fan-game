# 60 秒副歌模式 設計文件

**日期**：2026-09-09
**狀態**：設計已確認，待寫實作計畫

## 目標

在選歌時新增「60 秒副歌」時長選項：每首歌預先切出一段 60 秒的副歌/高潮片段，選了就從頭播、限時 60 秒遊玩。

## 核心原則

**全部是一次性離線預處理**，最終只產出 6 支 60 秒短片 + 遊戲多一個選項。
- 偵測與切片程式是**開發時跑一次的腳本**，不進 `build`、不進遊戲執行期、不新增遊戲依賴。
- 遊戲唯一改動 = 選歌多一個時長選項 + 載對應短片。
- 不使用 librosa/pychorus（Python 3.13 上 numba 依賴脆弱）；只用**已安裝的 numpy/scipy + ffmpeg**。

## 資料流

```
public/mv/{id}.mp4  ──(離線腳本)──▶  偵測副歌起點(秒)  ──(人眼複核/微調)──▶
  ffmpeg 切 60s +faststart  ──▶  public/mv/{id}-chorus.mp4
遊戲：選「60秒副歌」──▶ pickPlayback(track,'chorus') ──▶ {src:{id}-chorus.mp4, roundSec:60}
```

## 元件

### 1. 離線偵測腳本 `tools/detect-chorus.py`（開發用，不進 build）

輸入：`public/mv/` 下 6 支已裁切的 mp4。輸出：`tools/chorus-times.json`（`{ id: 副歌起始秒數 }`），供人眼複核。

- **共用前處理**：ffmpeg 解碼成單聲道 WAV（22050 Hz），用 `scipy.io.wavfile` 讀進 numpy。
- **A 法（4 首流行：canon-rock、super-run、initial-d、bumblebee）**：
  - numpy `rfft` 對每個時間框（hop ~0.5s）算頻譜，折疊成 **12 音級 chroma 向量**。
  - 建 chroma 的**時間自相似矩陣**（cosine），沿時間-延遲方向找**最常重複且持續**的段落起點（pychorus 核心算法，自行以 numpy 實作）。
  - 回傳該重複段起始秒數。
- **B 法（2 首國樂：dragon-boat、golden-snake）**：
  - ffmpeg `ebur128`（或 numpy 對窗 RMS）取**響度包絡**。
  - 滑動 60 秒視窗，找**平均能量最高**的視窗；回傳該視窗（往前含前奏前）的起點。
- 腳本印出每首結果 + 建議切點，寫入 JSON。**不自動上線**。

### 2. 切片（ffmpeg，開發時執行）

對每首：
```
dur = 該 mp4 長度
start = clamp(chorusStart - LEAD_IN, 0, max(0, dur - 60))   # LEAD_IN = 2.5s 前奏
len   = min(60, dur)
ffmpeg -y -ss {start} -i public/mv/{id}.mp4 -t {len} \
  -c:v libx264 -preset veryfast -crf 23 -c:a aac -b:a 128k -movflags +faststart \
  public/mv/{id}-chorus.mp4
```
- 邊界：副歌太靠結尾 → `dur-60` 讓片段收在曲末。整片<60s → 用整片。
- 產出後**逐首人眼確認**；抓歪就手改 `chorus-times.json` 的秒數重切。

### 3. 遊戲改動

**唯一動到遊戲的部分。**

- **`src/tracks.js`**：不需新欄位，副歌 src 由 `${base}mv/${id}-chorus.mp4` 推導（6 首都會有）。
- **純函數 `pickPlayback(track, lenMode)`**（放 `src/tracks.js`，**有單元測試**）：
  - 回傳 `{ src, roundSec }`，其中 `roundSec` 為 **固定值或 `null`**（`null` = 「開播後由 MV `loadedmetadata` 的 duration 決定」，沿用現行邏輯）。
  - `lenMode === 'chorus'` → `{ src: `${base}mv/${id}-chorus.mp4`, roundSec: 60 }`（固定 60，不看 duration）
  - `lenMode === '2'` → `{ src: track.src, roundSec: null }`（開播後 `min(120, duration)`）
  - 其他（完整曲）→ `{ src: track.src, roundSec: null }`（開播後 = duration）
  - 單元測試只驗 `src` 與 chorus 的固定 `roundSec:60`、其餘 `roundSec:null`；duration 相關計算仍在 `loadedmetadata` handler，維持現狀。
- **選歌畫面 `select-screen.js`**：時長選項由「2分鐘 / 完整曲」→「**60秒副歌 / 2分鐘 / 完整曲**」。lenMode 新值 `'chorus'`。
- **`src/main.js` startPlaying**：改用 `pickPlayback` 決定 `mvVideo.src` 與 `roundSec`；chorus 模式時 roundSec 直接 60、`chart = chartFromBpm(bpm, stars, 60)`。
- **載入 `music.js`**：chorus 短片小（~4MB），選到該模式時由 `media.prep` 載入，不動開機全預載。

## 測試

- **偵測/切片腳本**：一次性，**靠人眼複核切出的片段**是否命中副歌/高潮；不對就手調秒數重切。無自動測試。
- **`pickPlayback` 純函數**：單元測試三種 lenMode 各回正確 `{src, roundSec}`（含 chorus 固定 60）。
- **實機**：三種時長選項各跑一首；6 首副歌片各聽開頭確認命中且從頭乾淨起播。

## 風險與取捨

- **國樂無真正「副歌」**：B 法抓的是「最高潮的持續段」（金蛇狂舞後段急板齊奏會被抓到）——這是刻意設計。
- **流行歌 chroma 可能抓歪**：切完**逐首人眼複核**、必要時手動微調秒數重切，不盲切上線。
- **無新依賴**：只用 numpy/scipy/ffmpeg，避開 librosa/numba 在 Python 3.13 的安裝風險。
- **YAGNI**：不做遊戲執行期即時偵測、不做每首多段副歌、不自動化「腳本→上線」流水線（6 首手動複核即可）。

## 不做（明確排除）

- 遊戲執行期即時音訊分析（那是先前討論的 (乙) 方案，已否決）。
- 副歌時間存進 tracks.js（不需要；短片本身從 0 播）。
- 對未來新增歌曲自動偵測（新增歌時再跑一次腳本即可）。
